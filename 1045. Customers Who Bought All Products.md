# 1045. Customers Who Bought All Products
LeetCode: https://leetcode.com/problems/customers-who-bought-all-products/ · Medium

## Problem
Return the `customer_id` of every customer who has purchased every product listed in `Product`.

**Customer**
| Column | Type | Notes |
|---|---|---|
| customer_id | int | |
| product_key | int | foreign key into Product, may repeat |

**Product**
| Column | Type | Notes |
|---|---|---|
| product_key | int | primary key |

**Example**
```
Customer: (1, 10), (1, 10), (1, 20), (1, 30), (2, 10), (2, 20)
Product: (10), (20), (30)

Output: customer_id = 1
```
Customer 1 has purchase records covering all three products (the extra `10` is just a duplicate row). Customer 2 only ever bought two of the three, so they're excluded.

## Solution
```sql
SELECT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(*)
    FROM Product
);
```

1. The subquery `SELECT COUNT(*) FROM Product` gives the total number of products that exist: 3.
2. `GROUP BY customer_id` buckets each customer's purchase rows together, and `COUNT(DISTINCT product_key)` counts how many *unique* products they bought, not how many rows they have. That distinction matters because `Customer` allows duplicates: customer 1 has 4 rows but only 3 distinct products.
3. `HAVING` is used instead of `WHERE` because the filter compares an aggregated value (the distinct count), which only exists after grouping.
4. Customer 1's distinct product count (3) matches the total (3), so they're included. Customer 2's distinct count (2) doesn't match, so they're filtered out.

**Follow-up:** a correlated `NOT EXISTS` version expresses the same idea more literally: "there is no product for which this customer has no matching purchase row." It's a useful pattern to know for any "bought/did all of X" question, since it doesn't rely on counting and works even without a clean total to compare against.

**Can this be done with a join instead?** Yes, and it gives the same result:
```sql
SELECT c.customer_id
FROM Customer c
JOIN Product p ON c.product_key = p.product_key
GROUP BY c.customer_id
HAVING COUNT(DISTINCT c.product_key) = (SELECT COUNT(*) FROM Product);
```
It's just unnecessary here. `product_key` in `Customer` is a foreign key into `Product`, so every purchase row already points at a real product, and joining to `Product` can't filter out or add anything. The join would start to matter if `Customer` could ever contain a `product_key` that doesn't exist in `Product`; then the join would drop those bad rows before counting, and skipping it could let a nonexistent product inflate someone's distinct count. That situation is ruled out by this problem's schema, so the plain `GROUP BY` on `Customer` gets the same answer with less work.

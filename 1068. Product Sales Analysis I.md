# 1068. Product Sales Analysis I
LeetCode: https://leetcode.com/problems/product-sales-analysis-i/ · Easy

## Problem
Report `product_name`, `year`, and `price` for every sale in `Sales`, in any order.

**Sales**
| Column | Type | Notes |
|---|---|---|
| sale_id | int | |
| product_id | int | foreign key into Product |
| year | int | part of the composite primary key |
| quantity | int | |
| price | int | |

**Product**
| Column | Type | Notes |
|---|---|---|
| product_id | int | primary key |
| product_name | varchar | |

**Example**
```
Sales: (sale_id 1, product_id 100, year 2008, price 5000), (sale_id 7, product_id 200, year 2011, price 9000)
Product: (100, Nokia), (200, Apple)

Output:
product_name | year | price
Nokia        | 2008 | 5000
Apple        | 2011 | 9000
```

## Solution
```sql
SELECT p.product_name, s.year, s.price
FROM Sales s
INNER JOIN Product p
ON s.product_id = p.product_id;
```

`product_id` in `Sales` is a foreign key into `Product`, so every sale is guaranteed a matching product row; the inner join just pulls in `product_name` alongside the `year` and `price` already sitting in `Sales`. A `LEFT JOIN` would return the identical result here since nothing can go unmatched, but `INNER JOIN` states the actual intent more clearly: return sales that have a product, which is all of them.

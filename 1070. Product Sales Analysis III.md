# 1070. Product Sales Analysis III
LeetCode: https://leetcode.com/problems/product-sales-analysis-iii/ · Medium

## Problem
For each `product_id`, find its first year of sale, then return every sales row from that first year (`product_id`, `first_year`, `quantity`, `price`), in any order.

**Sales**
| Column | Type | Notes |
|---|---|---|
| sale_id | int | |
| product_id | int | |
| year | int | |
| quantity | int | |
| price | int | |

**Example**
```
sale_id | product_id | year | quantity | price
1       | 100        | 2008 | 10       | 5000
2       | 100        | 2008 | 20       | 4500
3       | 100        | 2009 | 12       | 5000

Output:
product_id | first_year | quantity | price
100        | 2008       | 10       | 5000
100        | 2008       | 20       | 4500
```
Product 100's first year is 2008, and both 2008 rows come back since the question asks for the whole first year, not just the first sale within it. The 2009 row is dropped.

## Solution
```sql
SELECT s.product_id,
       f.first_year,
       s.quantity,
       s.price
FROM Sales s
JOIN (
    SELECT product_id, MIN(year) AS first_year
    FROM Sales
    GROUP BY product_id
) f
ON s.product_id = f.product_id
AND s.year = f.first_year;
```

1. The derived table `f` computes each product's earliest year with a plain `GROUP BY` + `MIN(year)`. This alone can't return `quantity`/`price` per row, since those get collapsed by the grouping.
2. The join back to `Sales` restores row-level detail, but it needs both `s.product_id = f.product_id` and `s.year = f.first_year`; matching on product alone would pull in every year, including 2009.
3. Because sale_id 1 and 2 both fall in 2008, both survive the join. That's the point of joining back rather than trying to answer this with a single `GROUP BY` pass, which could only ever emit one row per product.

A window-function version replaces the derived table with `RANK() OVER (PARTITION BY product_id ORDER BY year)` and filters `WHERE rnk = 1` in an outer query. `RANK()` (not `ROW_NUMBER()`) matters here, since it assigns the same rank to tied years, so all of a product's first-year rows keep rank 1 instead of just one of them being picked arbitrarily.

# 1075. Project Employees I
LeetCode: https://leetcode.com/problems/project-employees-i/ · Easy

## Problem
For each project, return the average `experience_years` of the employees working on it, rounded to 2 decimal places, in any order.

**Project**
| Column | Type | Notes |
|---|---|---|
| project_id | int | |
| employee_id | int | foreign key into Employee |

**Employee**
| Column | Type | Notes |
|---|---|---|
| employee_id | int | primary key |
| name | varchar | |
| experience_years | int | |

**Example**
```
Project: (1,1), (1,2), (1,3), (2,1), (2,4)
Employee: (1, 3 yrs), (2, 2 yrs), (3, 1 yr), (4, 2 yrs)

Output:
project_id | average_years
1          | 2.00
2          | 2.50
```
Project 1's team (employees 1, 2, 3) has experience `3, 2, 1`, averaging 2.00. Project 2's team (employees 1, 4) has `3, 2`, averaging 2.50.

## Solution
```sql
SELECT p.project_id,
       ROUND(AVG(e.experience_years), 2) AS average_years
FROM Project p
JOIN Employee e
ON p.employee_id = e.employee_id
GROUP BY p.project_id;
```

1. The join attaches each project assignment to that employee's `experience_years`, then `GROUP BY p.project_id` buckets rows by project so `AVG()` runs per project rather than across the whole table.
2. A plain `JOIN` (inner) is enough because `Project.employee_id` is a foreign key into `Employee`, so every assignment is guaranteed a match; nothing gets silently dropped the way it could with an unconstrained foreign key.
3. `ROUND(..., 2)` is applied to the aggregate, not to each row, which is why it appears once around `AVG()` rather than around `experience_years`.

Swapping in a `LEFT JOIN` here produces the same result, since the foreign key guarantees a match either way; it's worth remembering that a foreign key alone doesn't dictate the join type; it just means, in this particular case, the two choices happen to be equivalent.

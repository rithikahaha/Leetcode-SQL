# 1141. User Activity for the Past 30 Days I
LeetCode: https://leetcode.com/problems/user-activity-for-the-past-30-days-i/ · Easy

## Problem
For the 30-day window ending 2019-07-27 (inclusive), return the number of distinct active users for each day that had any activity. Any activity type counts.

**Activity**
| Column | Type | Notes |
|---|---|---|
| user_id | int | |
| session_id | int | |
| activity_date | date | |
| activity_type | enum | open_session, end_session, scroll_down, send_message |

**Example**
```
Activity:
user_id | session_id | activity_date | activity_type
1       | 1          | 2019-07-20    | open_session
1       | 1          | 2019-07-20    | scroll_down
1       | 1          | 2019-07-20    | end_session
2       | 4          | 2019-07-20    | open_session
2       | 4          | 2019-07-21    | send_message
2       | 4          | 2019-07-21    | end_session
3       | 2          | 2019-07-21    | open_session

Output:
day        | active_users
2019-07-20 | 2
2019-07-21 | 2
```
On 2019-07-20, user 1 logs three activities but counts once; user 2 logs one. That's 2 distinct users, not 4 rows.

## Solution
```sql
SELECT activity_date AS day,
       COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
GROUP BY activity_date;
```

1. The window is 30 days ending 2019-07-27 inclusive, so the start date is 2019-06-28. `BETWEEN` is inclusive on both ends, which matches that requirement exactly.
2. `COUNT(DISTINCT user_id)` is what makes this "active users" rather than "activity count": a user with three activities in one day should only be counted once.
3. No filter on `activity_type` is needed, since the problem says every activity type counts as being active.
4. Days with zero activity never show up in `Activity` to begin with, so `GROUP BY activity_date` naturally omits them without any extra handling.

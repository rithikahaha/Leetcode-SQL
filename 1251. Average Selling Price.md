# 1251. Average Selling Price
LeetCode: https://leetcode.com/problems/average-selling-price/ · Easy

## Problem
For each product, find the average selling price: total revenue divided by total units sold, where revenue is `Σ(price × units)` across the date range each price was in effect. Products with no sales report 0.

**Prices**
| Column | Type | Notes |
|---|---|---|
| product_id | int | |
| start_date | date | price period start |
| end_date | date | price period end, periods don't overlap per product |
| price | int | |

**UnitsSold**
| Column | Type | Notes |
|---|---|---|
| product_id | int | |
| purchase_date | date | |
| units | int | |

**Example**
```
Prices: (1, 2019-02-17, 2019-02-28, 5), (1, 2019-03-01, 2019-03-22, 20)
UnitsSold: (1, 2019-02-25, 100), (1, 2019-03-01, 15)
Output: (1, 6.96)
```
2019-02-25 falls in the first price period (5/unit, 100 units = 500), 2019-03-01 falls in the second (20/unit, 15 units = 300); (500 + 300) / 115 ≈ 6.96.

## Solution
```sql
SELECT p.product_id,
       ROUND(
           COALESCE(SUM(p.price * u.units) / SUM(u.units), 0),
           2
       ) AS average_price
FROM Prices p
LEFT JOIN UnitsSold u
    ON p.product_id = u.product_id
   AND u.purchase_date BETWEEN p.start_date AND p.end_date
GROUP BY p.product_id;
```

1. The join condition does double duty: it matches sales to their product, and it uses `BETWEEN` to pick out the one price period active on each `purchase_date`.
2. `LEFT JOIN` (not inner) keeps products with zero sales in the result; for those, `u.units` and the whole `SUM()` expression come back null.
3. `SUM(price * units) / SUM(units)` is a weighted average, not `AVG(price)`, since it needs to weight each price by how many units sold at it, not treat every sale row equally.
4. `COALESCE(..., 0)` catches the null from a product with no matching sales and reports 0 as the problem requires. `IFNULL()` does the same thing but is MySQL-specific; `COALESCE()` is the portable, standard version.

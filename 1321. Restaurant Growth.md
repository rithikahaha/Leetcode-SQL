# 1321. Restaurant Growth
LeetCode: https://leetcode.com/problems/restaurant-growth/ · Medium

## Problem
Compute a 7-day moving sum and average of daily revenue for a restaurant, returned only for dates that have a full trailing 7-day window.

**Customer**
| Column | Type | Notes |
|---|---|---|
| customer_id | int | part of primary key (customer_id, visited_on) |
| name | varchar | |
| visited_on | date | part of primary key |
| amount | int | amount paid on that visit |

A customer visits at most once per date, but multiple customers can visit on the same date.

**Example**
```
Customer: (1, Jhon, 2019-01-01, 100), (2, Daniel, 2019-01-02, 110), (3, Jade, 2019-01-03, 120),
          (4, Khaled, 2019-01-04, 130), (5, Winston, 2019-01-05, 110), (6, Elvis, 2019-01-06, 140),
          (7, Anna, 2019-01-07, 150), (8, Maria, 2019-01-08, 80), (9, Jaze, 2019-01-09, 110),
          (1, Jhon, 2019-01-10, 130), (3, Jade, 2019-01-10, 150)

Output:
visited_on | amount | average_amount
2019-01-07 | 860    | 122.86
2019-01-08 | 840    | 120.00
2019-01-09 | 840    | 120.00
2019-01-10 | 1000   | 142.86
```
January 10 has two visits (130 + 150 = 280), and Jan 1-6 are dropped since none of them has six full days behind it yet.

## Solution
```sql
SELECT
    visited_on,
    SUM(daily_amount) OVER (
        ORDER BY visited_on
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS amount,
    ROUND(
        AVG(daily_amount) OVER (
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ),
        2
    ) AS average_amount
FROM (
    SELECT visited_on, SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
) d
WHERE visited_on >= (
    SELECT DATE_ADD(MIN(visited_on), INTERVAL 6 DAY) FROM Customer
)
ORDER BY visited_on;
```

1. The inner query collapses same-day visits first (`SUM(amount) GROUP BY visited_on`), so Jan 10's two visits become a single row of 280. Skip that and the window would treat two visits on the same day as two separate days, corrupting the 7-day math.
2. `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` grabs the current row plus the six before it, exactly 7 rows. Because the problem guarantees a visit every day, 7 rows always means 7 consecutive calendar days, so counting physical rows (`ROWS`) is enough; there's no need for `RANGE`, which would look at the date values themselves.
3. For Jan 7 the window covers Jan 1-7: 100+110+120+130+110+140+150 = 860, average 860/7 ≈ 122.86.
4. For Jan 10 the window slides to Jan 4-10, and 280 (that day's combined total) is part of the sum: 130+110+140+150+80+110+280 = 1000.
5. The `WHERE` clause removes Jan 1 through Jan 6 by comparing against the earliest visit date plus 6 days, computed dynamically rather than hardcoded.

A self-join version exists too: join the daily-totals subquery to itself on `d2.visited_on BETWEEN d1.visited_on - 6 days AND d1.visited_on`, then `GROUP BY d1.visited_on HAVING COUNT(*) = 7`. It gives the same result without window functions, but window functions are the more natural tool for a moving average like this.

# 1327. List the Products Ordered in a Period
LeetCode: https://leetcode.com/problems/list-the-products-ordered-in-a-period/ · Easy

## Problem
Find products with at least 100 units ordered during February 2020. Return `product_name` and the total `unit` count for each.

**Products**
| Column | Type | Notes |
|---|---|---|
| product_id | int | primary key |
| product_name | varchar | |
| product_category | varchar | |

**Orders**
| Column | Type | Notes |
|---|---|---|
| product_id | int | foreign key -> Products.product_id |
| order_date | date | |
| unit | int | units ordered; table may have duplicate rows |

**Example**
```
Products: (1, Leetcode Solutions), (2, Jewels of Stringology), (3, HP), (5, Leetcode Kit)

Orders:
product_id | order_date | unit
1          | 2020-02-05 | 60
1          | 2020-02-10 | 70
2          | 2020-01-18 | 30
2          | 2020-02-11 | 80
3          | 2020-02-17 | 2
3          | 2020-02-24 | 3
5          | 2020-02-25 | 50
5          | 2020-02-27 | 50

Output:
product_name       | unit
Leetcode Solutions | 130
Leetcode Kit        | 100
```
Product 1 clears the bar with 60+70=130. Product 2's January order doesn't count, leaving only 80 in February, so it's excluded. Product 3 totals just 5. Product 5 lands exactly on the 100 threshold and is included since the requirement is "at least."

## Solution
```sql
SELECT
    p.product_name,
    SUM(o.unit) AS unit
FROM Products p
JOIN Orders o
    ON p.product_id = o.product_id
WHERE o.order_date >= '2020-02-01'
  AND o.order_date < '2020-03-01'
GROUP BY p.product_id, p.product_name
HAVING SUM(o.unit) >= 100;
```

1. `order_date >= '2020-02-01' AND order_date < '2020-03-01'` is a half-open range that grabs all of February regardless of whether it has 28 or 29 days, which is safer than hardcoding `<= '2020-02-29'`.
2. The join is a plain `INNER JOIN`: any product with no February orders can't reach 100 units anyway, so there's no need to keep it around with a `LEFT JOIN`.
3. `SUM(o.unit)` is used instead of `COUNT(*)` because the question asks for total units ordered, not number of order rows, and `Orders` can have duplicate rows that each legitimately add to the total.
4. `HAVING SUM(o.unit) >= 100` filters on the aggregate after grouping. `WHERE` can't do this, since `SUM()` doesn't exist yet at the row-filtering stage; it's only computed once rows are grouped by product.

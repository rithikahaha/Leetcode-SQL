# 1341. Movie Rating
LeetCode: https://leetcode.com/problems/movie-rating/ · Medium

## Problem
Return two results in a single column called `results`: the name of the user who has rated the most movies (ties broken by the lexicographically smaller name), and the title of the movie with the highest average rating in February 2020 (ties broken the same way).

**Movies**
| Column | Type | Notes |
|---|---|---|
| movie_id | int | primary key |
| title | varchar | unique |

**Users**
| Column | Type | Notes |
|---|---|---|
| user_id | int | primary key |
| name | varchar | unique |

**MovieRating**
| Column | Type | Notes |
|---|---|---|
| movie_id | int | |
| user_id | int | |
| rating | int | |
| created_at | date | |

Primary key is `(movie_id, user_id)`, so a user rates a given movie at most once.

**Example**
```
Ratings (all Feb 2020 unless noted):
Daniel  → Avengers 4, Frozen 2 5, Joker 3
Monica  → Avengers 2, Frozen 2 2, Joker 4
Maria   → Avengers 5 (Jan), Frozen 2 1 (Mar)
James   → Joker 5 (Jan)

Output: results = ('Daniel', 'Frozen 2')
```
Daniel and Monica both rated 3 movies, but "Daniel" < "Monica" lexicographically. For February, Frozen 2 and Joker tie at an average of 3.5, and "Frozen 2" < "Joker".

## Solution
```sql
SELECT results
FROM (
    SELECT u.name AS results
    FROM Users u
    JOIN MovieRating mr ON u.user_id = mr.user_id
    GROUP BY u.user_id, u.name
    ORDER BY COUNT(*) DESC, u.name
    LIMIT 1
) a

UNION ALL

SELECT results
FROM (
    SELECT m.title AS results
    FROM Movies m
    JOIN MovieRating mr ON m.movie_id = mr.movie_id
    WHERE mr.created_at >= '2020-02-01' AND mr.created_at < '2020-03-01'
    GROUP BY m.movie_id, m.title
    ORDER BY AVG(mr.rating) DESC, m.title
    LIMIT 1
) b;
```

1. Both halves follow the same shape: join to bring in the readable name, group to get one row per user (or movie), then `ORDER BY aggregate DESC, name` so the top count/average sorts first and a tie falls back to the smaller name.
2. `created_at >= '2020-02-01' AND created_at < '2020-03-01'` scopes the second query to February without a `BETWEEN`, which matters if the column ever carries a time component, not just a date.
3. Each subquery is wrapped before the `UNION ALL` because MySQL doesn't let two `ORDER BY ... LIMIT` clauses combine directly under a single `UNION ALL`; each `LIMIT 1` needs its own scope to guarantee it picks one row per side.
4. `UNION ALL` rather than `UNION`: these are two unrelated answers stacked into one column, and if they ever happened to be identical text, `UNION` would wrongly collapse them into one row.

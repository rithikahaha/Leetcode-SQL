# 1378. Replace Employee ID With The Unique Identifier
LeetCode: https://leetcode.com/problems/replace-employee-id-with-the-unique-identifier/ · Easy

## Problem
Show each employee's name alongside their `unique_id` from a separate lookup table, or null if they don't have one. Return in any order.

**Employees**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |

**EmployeeUNI**
| Column | Type | Notes |
|---|---|---|
| id | int | references Employees.id, not every employee has a row here |
| unique_id | int | |

**Example**
```
Employees: (1, Alice), (7, Bob), (11, Meir), (90, Winston), (3, Jonathan)
EmployeeUNI: (3, 1), (11, 2), (90, 3)
Output: (null, Alice), (null, Bob), (2, Meir), (3, Winston), (1, Jonathan)
```
Alice and Bob have no matching row in `EmployeeUNI`, so their `unique_id` comes back null.

## Solution
```sql
SELECT eu.unique_id, e.name
FROM Employees e
LEFT JOIN EmployeeUNI eu
    ON e.id = eu.id;
```

1. `Employees` has to be the left side of the join since every employee needs to show up in the output, whether or not they have a `unique_id`.
2. For a match, `eu.unique_id` comes through normally (Meir gets 2, Winston gets 3, Jonathan gets 1); for no match, `LEFT JOIN` fills `eu.unique_id` with null instead of dropping the row, which is exactly what Alice and Bob need.
3. A `RIGHT JOIN` with the tables swapped (`EmployeeUNI eu RIGHT JOIN Employees e`) produces the identical result; it's the same join, just written from the other side.

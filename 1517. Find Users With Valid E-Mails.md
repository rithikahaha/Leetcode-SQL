# 1517. Find Users With Valid E-Mails
LeetCode: https://leetcode.com/problems/find-users-with-valid-e-mails/ · Easy

## Problem
Return every user whose email starts with a letter, uses only letters/digits/underscore/period/dash in the prefix, and ends with the exact lowercase domain `@leetcode.com`.

**Users**
| Column | Type | Notes |
|---|---|---|
| user_id | int | primary key |
| name | varchar | |
| mail | varchar | |

**Example**
```
Users: (1, Winston, winston@leetcode.com), (2, Jonathan, jonathanisgreat),
       (3, Annabelle, bella-@leetcode.com), (4, Sally, sally.come@leetcode.com),
       (5, Marwan, quarz#2020@leetcode.com), (6, David, david69@gmail.com),
       (7, Shapiro, .shapo@leetcode.com)

Output: (1, Winston, winston@leetcode.com), (3, Annabelle, bella-@leetcode.com),
        (4, Sally, sally.come@leetcode.com)
```
User 2 has no `@` domain at all, 5 has a `#` in the prefix, 6 is on the wrong domain, and 7's prefix starts with a period instead of a letter, so all four are excluded.

## Solution
```sql
SELECT user_id, name, mail
FROM Users
WHERE mail REGEXP '^[A-Za-z][A-Za-z0-9_.-]*@leetcode\\.com$';
```

1. `^[A-Za-z]` anchors the match to the start of the string and forces the first prefix character to be a letter, which is exactly why user 7's `.shapo@leetcode.com` fails: the first character is a period.
2. `[A-Za-z0-9_.-]*` allows zero or more letters, digits, underscores, periods, or dashes for the rest of the prefix. User 5's `#` isn't in that set, so `quarz#2020...` fails even though the rest of the string would otherwise be fine.
3. `@leetcode\\.com$` requires the literal domain at the very end. The backslash escapes the period so it matches an actual dot rather than "any character," and `$` blocks anything trailing after `.com`. That's what rules out user 6's `@gmail.com`.
4. The double backslash in the SQL string literal matters: MySQL's string parser consumes one level of escaping before `REGEXP` ever sees the pattern, so a single `\.` inside the quotes would just come out as `.` and lose its special meaning.
5. Users 1, 3, and 4 satisfy every piece at once (letter start, allowed prefix characters, exact domain), which is why they're the only rows returned.

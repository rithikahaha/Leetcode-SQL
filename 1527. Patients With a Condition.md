# 1527. Patients With a Condition
LeetCode: https://leetcode.com/problems/patients-with-a-condition/ · Easy

## Problem
Find patients who have a Type I Diabetes code, meaning some condition code in the space-separated `conditions` string starts with `DIAB1`.

**Patients**
| Column | Type | Notes |
|---|---|---|
| patient_id | int | primary key |
| patient_name | varchar | |
| conditions | varchar | zero or more space-separated condition codes |

**Example**
```
Patients: (1, Daniel, 'YFEV COUGH'), (2, Alice, ''), (3, Bob, 'DIAB100 MYOP'),
          (4, George, 'ACNE DIAB100'), (5, Alain, 'DIAB201')

Output: (3, Bob, 'DIAB100 MYOP'), (4, George, 'ACNE DIAB100')
```
Bob's first code starts with `DIAB1`; George's second code does too. Alain's `DIAB201` doesn't match the `DIAB1` prefix, and nobody has `DIAB1` glued onto another code (the way `XDIAB100` would be).

## Solution
```sql
SELECT patient_id, patient_name, conditions
FROM Patients
WHERE conditions LIKE 'DIAB1%'
   OR conditions LIKE '% DIAB1%';
```

1. A code counts only if `DIAB1` starts it, not if it merely appears inside one, so a bare `LIKE '%DIAB1%'` would wrongly match something like `XDIAB100`.
2. `LIKE 'DIAB1%'` catches the case where the matching code is first in the string (Bob's `DIAB100 MYOP`).
3. `LIKE '% DIAB1%'` catches the case where it comes after another code, requiring a literal space right before `DIAB1` (George's `ACNE DIAB100`).
4. The two patterns are combined with `OR` because either position is valid; `AND` would require both to be true at once, which no single string can satisfy.
5. Alain's `DIAB201` fails both patterns since it starts with `DIAB2`, not `DIAB1`.

Wrapping `conditions` in spaces with `CONCAT(' ', conditions, ' ')` and matching one pattern, `LIKE '% DIAB1%'`, against that result is an equivalent single-pattern version of the same idea: it turns the start of the string into a fake "after a space" position too, so you don't need the separate `LIKE 'DIAB1%'` case.

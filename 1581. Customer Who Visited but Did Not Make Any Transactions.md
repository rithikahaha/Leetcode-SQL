# 1581. Customer Who Visited but Did Not Make Any Transactions
LeetCode: https://leetcode.com/problems/customer-who-visited-but-did-not-make-any-transactions/ · Easy

## Problem
Find customers who visited the mall but made no transaction on that visit, along with how many such visits each had.

**Visits**
| Column | Type | Notes |
|---|---|---|
| visit_id | int | primary key |
| customer_id | int | |

**Transactions**
| Column | Type | Notes |
|---|---|---|
| transaction_id | int | primary key |
| visit_id | int | foreign key -> Visits.visit_id |
| amount | int | |

**Example**
```
Visits: (1,23) (2,9) (4,30) (5,54) (6,96) (7,54)

Transactions:
transaction_id | visit_id | amount
2              | 5        | 310
3              | 5        | 300
9              | 5        | 200
12             | 1        | 910
13             | 2        | 970

Output:
customer_id | count_no_trans
54          | 1
30          | 1
96          | 1
```
Visits 1, 2, and 5 all have a matching transaction, so those get dropped. Visits 4, 6, and 7 don't, leaving customers 30, 96, and 54 (visit 7) each with one untransacted visit.

## Solution
```sql
SELECT v.customer_id,
       COUNT(*) AS count_no_trans
FROM Visits v
LEFT JOIN Transactions t
    ON v.visit_id = t.visit_id
WHERE t.transaction_id IS NULL
GROUP BY v.customer_id;
```

1. `LEFT JOIN` keeps every row from `Visits` even when there's no matching row in `Transactions`, in which case all the `Transactions` columns come back `NULL` for that row.
2. `WHERE t.transaction_id IS NULL` is what actually isolates the visits with no transaction, since those are exactly the rows where the join found nothing to attach.
3. `COUNT(*)` counts rows per customer rather than a specific column. `COUNT(t.visit_id)` would be wrong here, since `t.visit_id` is NULL on every row left after the filter.

`NOT EXISTS` is a solid alternative: `SELECT customer_id FROM Visits v WHERE NOT EXISTS (SELECT 1 FROM Transactions t WHERE v.visit_id = t.visit_id) GROUP BY customer_id`. It reads as "for each visit, check whether any transaction references it," and unlike `NOT IN`, it doesn't break if a subquery column happens to contain NULLs.

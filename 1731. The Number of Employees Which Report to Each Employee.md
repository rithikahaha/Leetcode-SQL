# 1731. The Number of Employees Which Report to Each Employee
LeetCode: https://leetcode.com/problems/the-number-of-employees-which-report-to-each-employee/ · Easy

## Problem
For every employee with at least one direct report, return their `employee_id`, `name`, the count of direct reports, and the average age of those reports (rounded to the nearest integer), ordered by `employee_id`.

**Employees**
| Column | Type | Notes |
|---|---|---|
| employee_id | int | primary key |
| name | varchar | |
| reports_to | int | employee_id of this person's manager, null if none |
| age | int | |

**Example**
```
employee_id | name    | reports_to | age
1           | Michael | NULL       | 45
2           | Alice   | 1          | 38
3           | Bob     | 1          | 42
4           | Charlie | 2          | 34
5           | David   | 2          | 40
6           | Eve     | 3          | 37

Output:
employee_id | name    | reports_count | average_age
1           | Michael | 2             | 40
2           | Alice   | 2             | 37
3           | Bob     | 1             | 37
```
Charlie and David report to Alice, not Michael, so they only count toward Alice's average even though Alice ultimately reports to Michael.

## Solution
```sql
SELECT m.employee_id,
       m.name,
       COUNT(e.employee_id) AS reports_count,
       ROUND(AVG(e.age)) AS average_age
FROM Employees m
JOIN Employees e
    ON m.employee_id = e.reports_to
GROUP BY m.employee_id, m.name
ORDER BY m.employee_id;
```

1. This is a self join: `m` stands in for the manager side of the table, `e` for the report side, and `m.employee_id = e.reports_to` links each report to their direct manager only, since `reports_to` always holds the immediate manager's id, not a grandmanager's.
2. Using `JOIN` (inner) rather than `LEFT JOIN` is what makes the result automatically exclude non-managers: an employee only survives as `m` if at least one `e` row matches, which is exactly the definition of "has a direct report" here.
3. `COUNT(e.employee_id)` and `AVG(e.age)` operate on the report side per group, so for Michael's group (Alice, Bob) that's `COUNT = 2` and `AVG(38, 42) = 40`; `ROUND()` handles cases like Alice's group averaging 37 exactly, and would round a value like 38.5 up to 39.

# 176. Second Highest Salary
LeetCode: https://leetcode.com/problems/second-highest-salary/ · Medium

## Problem
Return the second highest **distinct** salary from `Employee(id, salary)`, or null if it doesn't exist.

**Employee**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| salary | int | |

**Example 1**
```
Employee: (1, 100), (2, 200), (3, 300)
Output: SecondHighestSalary = 200
```

**Example 2**
```
Employee: (1, 100)
Output: SecondHighestSalary = null   (only one distinct salary exists)
```

## Solution
```sql
SELECT MAX(salary) AS SecondHighestSalary
FROM Employee
WHERE salary < (
    SELECT MAX(salary)
    FROM Employee
);
```

1. The inner subquery finds the overall maximum first: 300.
2. `WHERE salary < 300` throws out the top salary and keeps everything strictly below it, here 100 and 200. This handles duplicates for free: if two people were tied at 300, both would still get excluded by `<`, instead of one of them getting mistaken for the "second" salary.
3. The outer `MAX()` then takes the largest of what's left, 200, which is the second-highest distinct salary.
4. When there's only one distinct salary (100), `WHERE salary < 100` matches zero rows, and `MAX()` over an empty set returns `NULL` automatically, exactly the output the problem wants, with no extra guard needed.

**Follow-up:** a `DISTINCT` + `ORDER BY salary DESC LIMIT 1 OFFSET 1` approach works too, but a bare version of that returns no row at all (not a null row) when there's no second salary. Wrapping it in an outer `SELECT (...)` fixes that, since a scalar subquery that matches nothing evaluates to `NULL` rather than disappearing.

# 177. Nth Highest Salary
LeetCode: https://leetcode.com/problems/nth-highest-salary/ · Medium

## Problem
Write a function `getNthHighestSalary(N)` that returns the Nth highest **distinct** salary from `Employee(id, salary)`, or null if it doesn't exist. Unlike 176 (fixed at "second"), N is a parameter passed in at call time.

**Employee**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| salary | int | |

**Example 1**
```
Employee: (1, 100), (2, 200), (3, 300)
N = 2
Output: getNthHighestSalary(2) = 200
```

**Example 2**
```
Employee: (1, 100)
N = 2
Output: getNthHighestSalary(2) = null   (only one distinct salary exists)
```

## Solution
```sql
CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT
BEGIN
    RETURN (
        SELECT DISTINCT salary
        FROM Employee
        ORDER BY salary DESC
        LIMIT 1 OFFSET N - 1
    );
END
```

1. Because N is only known when the function is called, this can't be a plain query like 176's; it has to be wrapped in `CREATE FUNCTION ... RETURNS INT` with N as a parameter.
2. `DISTINCT salary` plus `ORDER BY salary DESC` builds the same ranked list of unique salaries as 176 did: `[300, 200, 100]` for the first example.
3. `LIMIT 1 OFFSET N - 1` skips the first `N - 1` rows of that ranked list and takes the next one. `OFFSET` is zero-indexed, so asking for the 2nd highest means skipping 1 row, hence the `N - 1`.
4. When N is larger than the number of distinct salaries, as in Example 2 where N=2 but only one salary exists, the offset skips past every row and the subquery returns nothing. A scalar subquery that returns zero rows evaluates to `NULL`, which happens to be exactly the "return null" behavior the problem wants, no extra guard needed.

The problem's constraints guarantee N is a positive integer, so `N - 1` never goes negative here.

**Simpler alternative, avoids the OFFSET math entirely:** give every distinct salary a rank directly, then just ask for the row whose rank equals N.

```sql
CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT
BEGIN
    RETURN (
        SELECT salary FROM (
            SELECT DISTINCT salary,
                   DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank
            FROM Employee
        ) ranked
        WHERE salary_rank = N
    );
END
```
`DENSE_RANK()` numbers the highest salary 1, the next distinct one 2, and so on. That turns "the Nth highest" into literally `salary_rank = N`, no N-1 arithmetic anywhere. For the first example, 300 gets rank 1 and 200 gets rank 2, so N=2 matches the row with 200. If N is bigger than the number of distinct salaries, no row has that rank, the query returns nothing, and NULL comes back automatically, same as before. The `CREATE FUNCTION` wrapper is still required either way, that part isn't optional, it's how LeetCode's test harness calls your code with different values of N.

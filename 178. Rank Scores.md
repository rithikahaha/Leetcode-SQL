# 178. Rank Scores
LeetCode: https://leetcode.com/problems/rank-scores/ · Medium

## Problem
Rank scores from highest to lowest. Equal scores get the same rank, and ranking must not leave gaps after a tie (two people tied for 1st means the next distinct score is rank 2, not 3).

**Scores**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| score | decimal | |

**Example**
```
Scores: (1, 3.50), (2, 3.65), (3, 4.00), (4, 3.85), (5, 4.00), (6, 3.65)

Output (ordered by score descending):
score | rank
4.00  | 1
4.00  | 1
3.85  | 2
3.65  | 3
3.65  | 3
3.50  | 4
```
Both 4.00 rows tie for 1st. The next distinct score, 3.85, is rank 2, not 3, since dense ranking doesn't skip a number after a tie.

## Solution
```sql
SELECT score, DENSE_RANK() OVER (ORDER BY score DESC) AS `rank`
FROM Scores
ORDER BY score DESC;
```

1. `DENSE_RANK() OVER (ORDER BY score DESC)` numbers rows by descending score, giving identical scores the identical rank: both 4.00 rows get rank 1.
2. Unlike plain `RANK()`, `DENSE_RANK()` doesn't skip a number after a tie. After the two rank-1 rows, the next distinct score gets rank 2, not 3, matching the "no gaps" requirement.
3. `rank` is wrapped in backticks because it's a reserved keyword in MySQL 8+; without them the query wouldn't parse.
4. The outer `ORDER BY score DESC` is needed separately from the window function's own ordering, since a window function only computes a value per row, it doesn't change the actual row order of the result set.

**Alternative without window functions:** for each score, count how many distinct scores are greater than or equal to it: `(SELECT COUNT(DISTINCT s2.score) FROM Scores s2 WHERE s2.score >= s.score)`. That count is the rank directly, since a score ties with itself once and is only beaten by strictly higher distinct scores. Useful on databases without `DENSE_RANK()`, but it re-scans the table once per row instead of computing everything in a single pass.

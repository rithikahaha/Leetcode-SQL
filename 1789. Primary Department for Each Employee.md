# 1789. Primary Department for Each Employee
LeetCode: https://leetcode.com/problems/primary-department-for-each-employee/ · Easy

## Problem
Return each employee's primary department: the one flagged `'Y'`, or their only department if they belong to just one (in which case the flag is `'N'`).

**Employee**
| Column | Type | Notes |
|---|---|---|
| employee_id | int | part of primary key (employee_id, department_id) |
| department_id | int | part of primary key |
| primary_flag | varchar | 'Y' or 'N' |

**Example**
```
Employee: (1,1,N), (2,1,Y), (2,2,N), (3,3,N), (4,2,N), (4,3,Y), (4,4,N)

Output: (1,1), (2,1), (3,3), (4,3)
```
Employees 1 and 3 each have only one department, so it counts as primary despite the `'N'` flag; employees 2 and 4 have their `'Y'`-flagged row picked instead.

## Solution
```sql
SELECT employee_id, department_id
FROM Employee
WHERE primary_flag = 'Y'
   OR employee_id IN (
       SELECT employee_id
       FROM Employee
       GROUP BY employee_id
       HAVING COUNT(*) = 1
   );
```

1. The subquery groups by `employee_id` and keeps only employees with exactly one row (`HAVING COUNT(*) = 1`), which is employees 1 and 3, the ones with no explicit primary flag set.
2. `WHERE primary_flag = 'Y'` independently picks up employees 2 and 4's flagged rows.
3. The two conditions are joined with `OR` since a row only needs to satisfy one of them; an employee with multiple departments never matches the subquery, so only their `'Y'` row makes it through.
4. `HAVING` is required instead of `WHERE` here because `COUNT(*)` is an aggregate that only exists after `GROUP BY` has run.

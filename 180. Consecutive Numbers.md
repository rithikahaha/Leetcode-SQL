# 180. Consecutive Numbers
LeetCode: https://leetcode.com/problems/consecutive-numbers/ · Medium

## Problem
Find every number that appears at least three times in a row in `Logs`.

**Logs**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key, auto-increment, defines row order |
| num | varchar | |

**Example**
```
Logs: (1,1), (2,1), (3,1), (4,2), (5,1), (6,2), (7,2)

Output: ConsecutiveNums = 1
```
Rows 1-3 all hold `1`, three in a row, so `1` qualifies. No other value repeats three times consecutively.

## Solution
```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT num,
           LAG(num, 1) OVER (ORDER BY id) AS prev_num,
           LAG(num, 2) OVER (ORDER BY id) AS prev_prev_num
    FROM Logs
) l
WHERE num = prev_num
  AND num = prev_prev_num;
```

1. `LAG(num, 1)` and `LAG(num, 2)` pull the value from one and two rows earlier (ordered by `id`), so each row can see itself plus its two predecessors without a self-join.
2. At `id=3`, `num=1`, `prev_num=1` (row 2), `prev_prev_num=1` (row 1); all three match, so `1` qualifies.
3. At `id=4`, `num=2` but `prev_num=1`, so the row fails the filter; rows 6-7 never accumulate three matching values either since only two 2's appear in a row.
4. `DISTINCT` matters for runs longer than three, where multiple consecutive rows would satisfy the `WHERE` clause for the same value and it should only be reported once.
5. `ORDER BY id` inside `OVER()` is what defines "previous row"; without it, the `LAG` values would be arbitrary.

A self-join solves the same problem without window functions: join `Logs` to itself twice more on `l2.id = l1.id + 1` and `l3.id = l1.id + 2`, then filter `WHERE l1.num = l2.num AND l2.num = l3.num`. It's equally valid, but `LAG()` scales more cleanly if the "at least N in a row" threshold ever changes.

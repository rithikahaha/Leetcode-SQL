# 185. Department Top Three Salaries
LeetCode: https://leetcode.com/problems/department-top-three-salaries/ · Hard

## Problem
A "high earner" is an employee whose salary is among the top three **unique** salaries in their department (ties all count, so a department can return more than 3 rows). Return `Department`, `Employee`, and `Salary` for every high earner.

**Employee**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |
| salary | int | |
| departmentId | int | foreign key to `Department.id` |

**Department**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |

**Example**
```
Employee (IT dept): Max 90000, Joe 85000, Randy 85000, Will 70000
Employee (Sales dept): Henry 80000, Sam 60000

Output:
IT     | Max   | 90000
IT     | Joe   | 85000
IT     | Randy | 85000
IT     | Will  | 70000
Sales  | Henry | 80000
Sales  | Sam   | 60000
```
IT's unique salaries are 90000, 85000, 70000, so all four IT employees make the cut even though Joe and Randy tie. Sales only has two unique salaries, so both of its employees qualify by default.

## Solution
```sql
SELECT
    d.name AS Department,
    e.name AS Employee,
    e.salary AS Salary
FROM (
    SELECT
        e.*,
        DENSE_RANK() OVER (
            PARTITION BY departmentId
            ORDER BY salary DESC
        ) AS salary_rank
    FROM Employee e
) e
JOIN Department d
    ON e.departmentId = d.id
WHERE e.salary_rank <= 3;
```

1. `PARTITION BY departmentId` restarts the ranking for every department, so IT salaries never get compared against Sales salaries.
2. `DENSE_RANK()` is the key choice here, not `ROW_NUMBER()` or `RANK()`. For IT it assigns Max → 1, Joe → 2, Randy → 2, Will → 3. `ROW_NUMBER()` would give Joe and Randy different numbers and wrongly bump Will out of the top 3. `RANK()` would give Will rank 4 (it skips a rank after a tie), also excluding him. `DENSE_RANK()` leaves no gaps, which matches "top three unique salaries" exactly.
3. `WHERE e.salary_rank <= 3` keeps everyone tied at or above the third distinct salary. For Sales, which only has two unique salaries, this condition never excludes anyone.
4. The window function only needs columns from `Employee`, so it runs in a subquery first; the join to `Department` afterward is just there to translate `departmentId` into a readable name.

**Alternative without window functions:** for each employee, count how many *distinct* salaries in their department are strictly higher than their own (`SELECT COUNT(DISTINCT e2.salary) FROM Employee e2 WHERE e2.departmentId = e.departmentId AND e2.salary > e.salary`), then keep rows where that count is less than 3. It reads a little more indirectly ("fewer than 3 unique salaries beat me" instead of "my rank is 3 or better") but produces the same result on databases without `DENSE_RANK()`.

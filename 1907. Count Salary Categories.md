# 1907. Count Salary Categories
LeetCode: https://leetcode.com/problems/count-salary-categories/ · Medium

## Problem
Count how many accounts fall into each of three salary bands: Low (`< 20000`), Average (`20000` to `50000` inclusive), and High (`> 50000`). All three categories must appear in the output, with `0` for any category that has no matching accounts.

**Accounts**
| Column | Type | Notes |
|---|---|---|
| account_id | int | primary key |
| income | int | monthly income |

**Example**
```
Accounts: (3, 108939), (2, 12747), (8, 87709), (6, 91796)

Output:
category        | accounts_count
Low Salary      | 1
Average Salary  | 0
High Salary     | 3
```
Only account 2 (12747) is under 20000. Nothing falls in the 20000-50000 band, so it still has to show up with a 0. The rest (108939, 87709, 91796) are all above 50000.

## Solution
```sql
SELECT 'Low Salary' AS category,
       COUNT(CASE WHEN income < 20000 THEN 1 END) AS accounts_count
FROM Accounts

UNION ALL

SELECT 'Average Salary' AS category,
       COUNT(CASE WHEN income BETWEEN 20000 AND 50000 THEN 1 END) AS accounts_count
FROM Accounts

UNION ALL

SELECT 'High Salary' AS category,
       COUNT(CASE WHEN income > 50000 THEN 1 END) AS accounts_count
FROM Accounts;
```

1. A plain `GROUP BY category` would only produce rows for categories that actually have accounts, so an empty Average Salary group would silently vanish instead of showing `0`. Running three independent queries, one per category, guarantees all three rows exist no matter what the data looks like.
2. `CASE WHEN income < 20000 THEN 1 END` returns `1` for a matching row and `NULL` otherwise (there's no `ELSE`). `COUNT()` only counts non-NULL values, so `COUNT(CASE WHEN ...)` counts rows matching the condition while still returning `0`, not `NULL`, when nothing matches, since the outer query still produces one row per `FROM Accounts` scan.
3. `UNION ALL`, not `UNION`, stacks the three one-row results together without checking for duplicates. That's fine since the category labels differ anyway, and it avoids paying for deduplication that isn't needed.
4. `BETWEEN 20000 AND 50000` is inclusive on both ends, so an income of exactly 20000 or 50000 lands in Average, matching the problem's stated ranges.

An equivalent way to write the same conditional count in MySQL is `SUM(income < 20000)`, since a boolean expression evaluates to `1`/`0`. It works identically here; `COUNT(CASE WHEN ...)` is just more explicit about what's being counted.

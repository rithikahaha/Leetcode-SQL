# 1934. Confirmation Rate
LeetCode: https://leetcode.com/problems/confirmation-rate/ · Medium

## Problem
For each user, return their confirmation rate: confirmed messages divided by total confirmation requests, rounded to 2 decimals, or 0 if they never requested one.

**Signups**
| Column | Type | Notes |
|---|---|---|
| user_id | int | primary key |
| time_stamp | datetime | |

**Confirmations**
| Column | Type | Notes |
|---|---|---|
| user_id | int | foreign key into Signups |
| time_stamp | datetime | |
| action | enum | `'confirmed'` or `'timeout'` |

**Example** (timestamps omitted, they don't affect the calculation)
```
Signups: user_id 3, 7, 2, 6
Confirmations: (3, timeout), (3, timeout), (7, confirmed), (7, confirmed),
               (7, confirmed), (2, confirmed), (2, timeout)

Output: (3, 0.00), (7, 1.00), (2, 0.50), (6, 0.00)
```
User 6 signed up but never requested a confirmation at all.

## Solution
```sql
SELECT s.user_id,
       ROUND(IFNULL(AVG(c.action = 'confirmed'), 0), 2) AS confirmation_rate
FROM Signups s
LEFT JOIN Confirmations c
    ON s.user_id = c.user_id
GROUP BY s.user_id;
```

1. `LEFT JOIN` keeps every signed-up user even if they have no `Confirmations` rows at all, like user 6, whose joined `action` comes back `NULL`.
2. `c.action = 'confirmed'` evaluates to `1` or `0` per row (MySQL treats boolean expressions as integers), so `AVG()` across those 1s and 0s is directly `confirmed / total`, no separate `SUM` and `COUNT` needed.
3. User 7 has three confirmed rows: `AVG = 3/3 = 1.00`. User 2 has one confirmed and one timeout: `AVG = 0.50`. User 3 has two timeouts: `AVG = 0.00`.
4. For user 6, `AVG(NULL)` returns `NULL` since there are no rows to average; `IFNULL(..., 0)` converts that into the required `0.00` instead of dropping the row or leaving it null.
5. `ROUND(..., 2)` formats every rate to the required two decimal places.

**Follow-up:** the same logic also works spelled out as `SUM(c.action = 'confirmed') / COUNT(c.action)`, or with a `CASE WHEN action = 'confirmed' THEN 1 ELSE 0 END` inside the `AVG()` for databases that don't implicitly cast booleans to integers. Both give identical results here.

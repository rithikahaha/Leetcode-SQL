# 196. Delete Duplicate Emails
LeetCode: https://leetcode.com/problems/delete-duplicate-emails/ · Easy

## Problem
Delete every row in `Person` whose email is a duplicate, keeping only the row with the smallest `id` for each email.

**Person**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| email | varchar | not guaranteed unique |

**Example**
```
Person: (1, john@example.com), (2, bob@example.com), (3, john@example.com)
Output: Person: (1, john@example.com), (2, bob@example.com)
```
`john@example.com` appears at id 1 and id 3; id 3 gets deleted, leaving only the smaller id.

## Solution
```sql
DELETE p1
FROM Person p1
JOIN Person p2
    ON p1.email = p2.email
   AND p1.id > p2.id;
```

1. This is a self join: `p1` and `p2` both point at `Person`, so each row gets compared against every other row that shares its email.
2. `p1.id > p2.id` is what turns "same email" into "duplicate to delete": it only matches when `p1` is the larger-id half of a pair, so the smallest id in any group of duplicates never satisfies the join and survives.
3. For id 1 vs id 3: `1 > 3` is false, so row 1 is never selected as `p1`; `3 > 1` is true, so row 3 matches and gets deleted.
4. `DELETE p1` tells MySQL to remove only the `p1`-side rows; `p2` exists purely to identify which rows those are.
5. A plain `DELETE ... WHERE email IN (SELECT email ... HAVING COUNT(*) > 1)` would be wrong here, since it deletes every row sharing a duplicated email, including the one you're supposed to keep.

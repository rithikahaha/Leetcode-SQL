# 197. Rising Temperature
LeetCode: https://leetcode.com/problems/rising-temperature/ · Easy

## Problem
Find the `id` of every day whose temperature was higher than the day before it.

**Weather**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| recordDate | date | |
| temperature | int | |

**Example**
```
Weather:
1 | 2015-01-01 | 10
2 | 2015-01-02 | 25
3 | 2015-01-03 | 20
4 | 2015-01-04 | 30

Output: id = 2, 4
```
Day 2 (25) beats day 1 (10) and day 4 (30) beats day 3 (20); day 3 (20) does not beat day 2 (25).

## Solution
```sql
SELECT w1.id
FROM Weather w1
JOIN Weather w2
ON w2.recordDate = DATE_SUB(w1.recordDate, INTERVAL 1 DAY)
WHERE w1.temperature > w2.temperature;
```

1. This is a self-join: `w1` is the "today" row and `w2` is a candidate "yesterday" row.
2. `w2.recordDate = DATE_SUB(w1.recordDate, INTERVAL 1 DAY)` only matches `w2` rows that are exactly one calendar day before `w1`. This matters because `recordDate` values aren't guaranteed to be consecutive; if a date is missing from the table, there's simply no match for that gap, rather than silently comparing against an older row.
3. `WHERE w1.temperature > w2.temperature` then keeps only the days where today's reading beat yesterday's.
4. Returning `w1.id` gives the id of the day that rose, not the day before it.

**Alternative with a window function:** `LAG(temperature) OVER (ORDER BY recordDate)` and `LAG(recordDate) OVER (ORDER BY recordDate)` pull yesterday's temperature and date into the current row without a join. You still need `DATEDIFF(recordDate, prev_date) = 1` as a guard, since `LAG()` just returns the previous row in sorted order, which isn't necessarily yesterday if a date is missing.

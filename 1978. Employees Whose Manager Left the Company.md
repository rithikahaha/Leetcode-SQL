# 1978. Employees Whose Manager Left the Company
LeetCode: https://leetcode.com/problems/employees-whose-manager-left-the-company/ · Easy

## Problem
Return the `employee_id` of employees earning strictly less than $30,000 whose manager no longer has a row in the table, ordered by `employee_id`.

**Employees**
| Column | Type | Notes |
|---|---|---|
| employee_id | int | primary key |
| name | varchar | |
| manager_id | int | id of this employee's manager, null if none |
| salary | int | |

When a manager leaves, their row is deleted, but employees who reported to them keep the old `manager_id`.

**Example**
```
employee_id | name      | manager_id | salary
3           | Mila      | 9          | 60301
12          | Antonella | NULL       | 31000
13          | Emery     | NULL       | 67084
1           | Kalel     | 11         | 21241
9           | Mikaela   | NULL       | 50937
11          | Joziah    | 6          | 28485

Output: employee_id = 11
```
Kalel earns under $30,000 too, but manager 11 (Joziah) still exists. Joziah earns under $30,000 and reports to manager 6, who has no row in the table, so only Joziah qualifies.

## Solution
```sql
SELECT employee_id
FROM Employees e
WHERE salary < 30000
  AND manager_id IS NOT NULL
  AND NOT EXISTS (
      SELECT 1
      FROM Employees m
      WHERE m.employee_id = e.manager_id
  )
ORDER BY employee_id;
```

1. `manager_id IS NOT NULL` filters out employees with no manager at all; that's a different situation from "manager left" and shouldn't be conflated with it.
2. The `NOT EXISTS` subquery asks, for each employee, whether a row with `employee_id` equal to their `manager_id` is still in the table. `SELECT 1` is just a placeholder since `EXISTS` only cares whether a row is found, not what it contains.
3. Tracing Joziah: `manager_id = 6`, and no row has `employee_id = 6`, so the subquery finds nothing and `NOT EXISTS` is true. Kalel's `manager_id = 11` does match a row (Joziah), so he's excluded even though his salary also qualifies.

The same logic reads as a self `LEFT JOIN Employees m ON e.manager_id = m.employee_id` with `WHERE m.employee_id IS NULL`: unmatched managers come back as `NULL` on the right side, which is the classic "find the unmatched rows" join pattern. Either approach works; `NOT EXISTS` tends to read more directly as "no such manager exists."

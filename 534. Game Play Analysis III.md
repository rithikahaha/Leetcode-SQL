# 534. Game Play Analysis III
LeetCode: https://leetcode.com/problems/game-play-analysis-iii/ · Medium

## Problem
For each player and date, report the total games played by that player up to and including that date (a running total over their login history), ordered by date within each player.

**Activity**
| Column | Type | Notes |
|---|---|---|
| player_id | int | part of the primary key |
| device_id | int | |
| event_date | date | part of the primary key |
| games_played | int | |

**Example**
```
Activity: (1, 2, 2016-03-01, 5), (1, 2, 2016-05-02, 6), (1, 3, 2017-06-25, 1),
          (3, 1, 2016-03-02, 0), (3, 4, 2018-07-03, 5)

Output:
player_id | event_date | games_played_so_far
1         | 2016-03-01 | 5
1         | 2016-05-02 | 11
1         | 2017-06-25 | 12
3         | 2016-03-02 | 0
3         | 2018-07-03 | 5
```
Player 1's total climbs 5, then 5+6=11, then 11+1=12 as each new date adds to the running sum. Player 3 is tracked separately from player 1, so their total starts over at 0.

## Solution
```sql
SELECT
    player_id,
    event_date,
    SUM(games_played) OVER (
        PARTITION BY player_id
        ORDER BY event_date
    ) AS games_played_so_far
FROM Activity;
```

1. `SUM(games_played) OVER (...)` is a running total rather than a collapsing aggregate: it adds up `games_played` from the start of the window through the current row, without merging rows into one the way a plain `GROUP BY SUM` would. This is the same running-total pattern 1204 uses.
2. `PARTITION BY player_id` restarts that running total for every player, so player 3's total never gets mixed in with player 1's.
3. `ORDER BY event_date` inside the window defines what "up to and including" means; without it, the running total would accumulate in an arbitrary row order instead of chronological order.
4. Tracing player 1: 2016-03-01 sums just itself (5), 2016-05-02 adds the row before it (5+6=11), 2017-06-25 adds all three (5+6+1=12).

**Alternative without window functions:** self-join each row to every row for the same player on or before its date, then sum.
```sql
SELECT
    a1.player_id,
    a1.event_date,
    SUM(a2.games_played) AS games_played_so_far
FROM Activity a1
JOIN Activity a2
    ON a1.player_id = a2.player_id
   AND a2.event_date <= a1.event_date
GROUP BY a1.player_id, a1.event_date;
```
For each row in `a1`, this matches every one of that player's rows up to and including that date in `a2`, then sums their `games_played`. It gets the same running total without a window function, but re-scans matching rows for every date instead of computing the whole running sum in one pass.

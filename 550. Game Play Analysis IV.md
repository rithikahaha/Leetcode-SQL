# 550. Game Play Analysis IV
LeetCode: https://leetcode.com/problems/game-play-analysis-iv/ · Medium

## Problem
For each player, find whether they logged in again on the day immediately after their first login. Return the fraction of all players for whom that's true, rounded to 2 decimal places.

**Activity**
| Column | Type | Notes |
|---|---|---|
| player_id | int | part of primary key |
| device_id | int | |
| event_date | date | part of primary key |
| games_played | int | |

**Example**
```
Activity:
1 | 2016-03-01
1 | 2016-03-02
2 | 2017-06-25
3 | 2016-03-02
3 | 2018-07-03

Output: fraction = 0.33
```
Player 1's first login is 2016-03-01 and they returned the very next day, so they count. Player 2 has only one login. Player 3's first login is 2016-03-02 but their next login is 2018-07-03, not the next day. Only 1 of 3 players qualifies, giving 0.33.

## Solution
```sql
SELECT ROUND(
           COUNT(DISTINCT a.player_id) /
           (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM Activity a
JOIN (
    SELECT player_id,
           MIN(event_date) AS first_date
    FROM Activity
    GROUP BY player_id
) f
ON a.player_id = f.player_id
AND a.event_date = DATE_ADD(f.first_date, INTERVAL 1 DAY);
```

1. The subquery `f` finds each player's earliest login with `MIN(event_date) GROUP BY player_id`, giving one row per player.
2. The join condition `a.event_date = DATE_ADD(f.first_date, INTERVAL 1 DAY)` only keeps rows from `a` that land exactly one calendar day after that player's first login. Since `Activity` has one row per player per day (it's part of the primary key), a match here means the player did come back the next day; no match means they didn't, and that player simply won't appear in the join.
3. `COUNT(DISTINCT a.player_id)` counts how many players survived the join, i.e. how many returned the day after their first login.
4. The denominator is a separate uncorrelated subquery counting all distinct players, independent of the join, so it isn't affected by which rows got filtered out above.

**Alternative with window functions:** `MIN(event_date) OVER (PARTITION BY player_id)` tags every row with that player's first login date without collapsing the rows, and `LEAD(event_date) OVER (PARTITION BY player_id ORDER BY event_date)` grabs each player's next login date. Filtering to `event_date = first_date` leaves one row per player, and `AVG(next_date = DATE_ADD(first_date, INTERVAL 1 DAY))` averages a 1/0 condition straight into the fraction, skipping the two-query division entirely.

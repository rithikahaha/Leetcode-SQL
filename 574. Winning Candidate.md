# 574. Winning Candidate
LeetCode: https://leetcode.com/problems/winning-candidate/ · Medium

## Problem
Return the name of the candidate who received the most votes. The test data guarantees exactly one winner.

**Candidate**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key |
| name | varchar | |

**Vote**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key, auto-increment |
| candidateId | int | foreign key to `Candidate.id` |

**Example**
```
Candidate: (1, A), (2, B), (3, C), (4, D), (5, E)
Vote: (1, 2), (2, 4), (3, 3), (4, 2), (5, 5)

Output: name = B
```
Candidate 2 (B) got two votes, in rows 1 and 4. Everyone else got one.

## Solution
```sql
SELECT c.name
FROM Vote v
JOIN Candidate c ON v.candidateId = c.id
GROUP BY c.id, c.name
ORDER BY COUNT(*) DESC
LIMIT 1;
```

1. Joining `Vote` to `Candidate` attaches a name to every vote row, so each vote now says who it was for.
2. `GROUP BY c.id, c.name` puts all of one candidate's votes into a single group. In the example, B's group has 2 rows and every other group has 1.
3. `ORDER BY COUNT(*) DESC` sorts the groups from most votes to fewest, and `LIMIT 1` keeps the top one. This only works because the problem promises a single winner. With a tie, `LIMIT 1` would quietly return just one of the tied candidates.
4. Candidates who got no votes never appear in the join at all, which is fine since they can't win.

A version that counts before joining does the grouping on `Vote` alone and looks up the name afterwards: `SELECT name FROM Candidate WHERE id = (SELECT candidateId FROM Vote GROUP BY candidateId ORDER BY COUNT(*) DESC LIMIT 1)`. It avoids joining every vote row to a name, which is a bit cheaper on a big table.

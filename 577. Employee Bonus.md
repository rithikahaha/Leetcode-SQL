# 577. Employee Bonus
LeetCode: https://leetcode.com/problems/employee-bonus/ · Easy

## Problem
Return the name and bonus of every employee whose bonus is under 1000, including employees who have no bonus record at all.

**Employee**
| Column | Type | Notes |
|---|---|---|
| empId | int | primary key |
| name | varchar | |
| supervisor | int | |
| salary | int | |

**Bonus**
| Column | Type | Notes |
|---|---|---|
| empId | int | foreign key into Employee |
| bonus | int | |

**Example**
```
Employee: (3, Brad, null, 4000), (1, John, 3, 1000), (2, Dan, 3, 2000), (4, Thomas, 3, 4000)
Bonus: (2, 500), (4, 2000)

Output: (Brad, null), (John, null), (Dan, 500)
```
Brad and John have no matching row in `Bonus`. Dan's bonus is under 1000. Thomas's 2000 bonus disqualifies him.

## Solution
```sql
SELECT e.name, b.bonus
FROM Employee e
LEFT JOIN Bonus b
    ON e.empId = b.empId
WHERE b.bonus < 1000
   OR b.bonus IS NULL;
```

1. `LEFT JOIN` keeps every employee even without a matching `Bonus` row, so Brad and John still appear with `b.bonus` as `NULL`.
2. `OR b.bonus IS NULL` is necessary because `b.bonus < 1000` alone would silently drop those rows: under SQL's three-valued logic, comparing `NULL < 1000` is neither true nor false, so it never passes the filter by itself.
3. Dan's 500 passes `500 < 1000`. Thomas's 2000 fails both conditions and is excluded.
4. Brad, John, and Dan come back; Thomas doesn't.

**Follow-up:** `WHERE COALESCE(b.bonus, 0) < 1000` collapses both conditions into a single comparison by substituting 0 for a missing bonus before comparing, a shorter equivalent that avoids the explicit `OR ... IS NULL`.

# 578. Get Highest Answer Rate Question
LeetCode: https://leetcode.com/problems/get-highest-answer-rate-question/ · Medium

## Problem
The answer rate of a question is the number of times it was answered divided by the number of times it was shown. Return the id of the question with the highest answer rate, as a column named `survey_log`. If two questions tie, return the one with the smaller `question_id`.

**SurveyLog**
| Column | Type | Notes |
|---|---|---|
| id | int | the user who acted |
| action | enum | `show`, `answer` or `skip` |
| question_id | int | |
| answer_id | int | null unless the action is `answer` |
| q_num | int | position of the question in the session |
| timestamp | int | |

There is no primary key, and duplicate rows are possible.

**Example**
```
SurveyLog:
id | action | question_id | answer_id | q_num | timestamp
5  | show   | 285         | null      | 1     | 123
5  | answer | 285         | 124124    | 1     | 124
5  | show   | 369         | null      | 2     | 125
5  | skip   | 369         | null      | 2     | 126

Output: survey_log = 285
```
Question 285 was shown once and answered once, a rate of 1. Question 369 was shown once and skipped, a rate of 0.

## Solution
```sql
SELECT question_id AS survey_log
FROM SurveyLog
GROUP BY question_id
ORDER BY SUM(action = 'answer') / SUM(action = 'show') DESC,
         question_id ASC
LIMIT 1;
```

1. `GROUP BY question_id` gives one group per question, so the sums below are per question.
2. In MySQL a comparison like `action = 'answer'` evaluates to 1 or 0, so `SUM(action = 'answer')` counts the answer rows and `SUM(action = 'show')` counts the show rows. Dividing them is the answer rate. For 285 that's 1 / 1 = 1, and for 369 it's 0 / 1 = 0.
3. `ORDER BY rate DESC, question_id ASC` puts the highest rate first, and the second sort key settles ties by the smaller id, which is exactly the tie rule in the problem.
4. `LIMIT 1` keeps the top row. The rate only needs to be computed inside `ORDER BY`, it never has to be selected, so no extra column shows up in the output.

On other databases where a comparison isn't a number, use `COUNT(CASE WHEN action = 'answer' THEN 1 END)` in place of `SUM(action = 'answer')`. A question that was never shown would divide by zero, and MySQL returns NULL for that, which sorts last under `DESC`, so it never wins.

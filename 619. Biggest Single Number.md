# 619. Biggest Single Number
LeetCode: https://leetcode.com/problems/biggest-single-number/ · Easy

## Problem
A "single number" appears exactly once in `MyNumbers`. Return the largest one, or `NULL` if none exists.

**MyNumbers**
| Column | Type | Notes |
|---|---|---|
| num | int | may contain duplicates |

**Example**
```
MyNumbers: 8, 8, 3, 3, 1, 4, 5, 6
Output: num = 6
```
1, 4, 5, and 6 each appear once; 6 is the largest of those. If instead every value repeated (say `8, 8, 7, 7, 3, 3, 3`), the query returns `NULL`.

## Solution
```sql
SELECT MAX(num) AS num
FROM (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(num) = 1
) AS single_numbers;
```

1. The inner query groups identical values together and `HAVING COUNT(num) = 1` keeps only the groups with exactly one row, i.e. the numbers that show up once: `1, 4, 5, 6`. `HAVING` is required here instead of `WHERE` because the filter is on an aggregate (`COUNT`), which isn't evaluated until after grouping.
2. Wrapping it in an outer `SELECT MAX(num)` matters: without it, `GROUP BY` alone would emit one row per single number, not the single largest one.
3. The outer `MAX()` also solves the "no single number" case for free. Aggregate functions return `NULL` over zero rows, so if the inner query comes back empty, the whole thing naturally returns `NULL` instead of an empty result set.

A correlated-subquery version does the same job differently: `SELECT MAX(num) FROM MyNumbers n WHERE (SELECT COUNT(*) FROM MyNumbers WHERE num = n.num) = 1`. For each row it recomputes how many times that value occurs in the whole table and keeps it only if that count is 1. It's less efficient on large tables than the single `GROUP BY` pass above, but it's a useful pattern to recognize for "count occurrences of this row's own value" problems.

# 626. Exchange Seats
LeetCode: https://leetcode.com/problems/exchange-seats/ · Medium

## Problem
Swap the seat ids of every pair of consecutive students: `(1,2), (3,4), (5,6), ...`. If the number of students is odd, the last one keeps their seat. Ids are a continuous sequence starting at 1.

**Seat**
| Column | Type | Notes |
|---|---|---|
| id | int | primary key, continuous from 1 |
| student | varchar | |

**Example**
```
Seat: (1, Abbot), (2, Doris), (3, Emerson), (4, Green), (5, Jeames)
Output: (1, Doris), (2, Abbot), (3, Green), (4, Emerson), (5, Jeames)
```
Ids 1 and 2 swap, 3 and 4 swap; id 5 has no partner (odd count), so Jeames stays put.

## Solution
```sql
SELECT
    CASE
        WHEN id % 2 = 1 AND id < (SELECT MAX(id) FROM Seat)
            THEN id + 1
        WHEN id % 2 = 0
            THEN id - 1
        ELSE id
    END AS id,
    student
FROM Seat
ORDER BY id;
```

1. Nothing is actually updated in the table; the query just computes what each student's new id should be and returns that, which is all LeetCode checks.
2. Odd ids move up by one (`id + 1`), even ids move down by one (`id - 1`); together that's exactly a swap within each `(odd, odd+1)` pair.
3. The `id < (SELECT MAX(id) FROM Seat)` guard on the odd branch only matters for a trailing odd id with no partner: without it, that student would get pushed to a seat that doesn't exist.
4. In the example `MAX(id) = 5`, so id 5 fails `id < 5` and falls through to `ELSE id`, staying at 5. Ids 1-4 swap normally: 1 ↔ 2, 3 ↔ 4.
